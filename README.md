# SN Adobe Analytic

Adobe Stock analytics & insights for contributors — a TAS Tracker-style tool
without the paywall. Search keywords, analyze contributor portfolios, explore
niche heat maps, and export results to CSV.

> **Status:** Phase 1 MVP. The full PRD spans four phases (~8 weeks); this
> codebase implements Phase 1 (search, auth, layout, data layer) plus skeleton
> pages for every Phase 2-4 feature so the entire sidebar is navigable.

## Tech stack

- **Next.js 14** (App Router) + **TypeScript**
- **Tailwind CSS** with PRD design tokens (dark navy sidebar, lavender bg)
- Custom Shadcn/UI-style primitives (button, card, input, badge, label, select)
- **NextAuth.js** (email/password + optional Google OAuth)
- **Prisma** ORM with **SQLite** locally (swap to Supabase Postgres for prod)
- **Cheerio + Axios** scraper module (stub in MVP — uses generated mock data)

## Getting started

```bash
# 1. Install dependencies
npm install

# 2. Configure env
cp .env.example .env
# (the defaults work for local dev)

# 3. Set up the database
npx prisma generate
npx prisma db push

# 4. Run the dev server
npm run dev
# -> http://localhost:3000
```

The app redirects `/` to `/search`. Try keywords like `business`, `nature`, or
`ai illustration`. All search results are currently generated by the mock data
module (`src/lib/mock-data.ts`) — the real Adobe Stock scraper lives in
`src/lib/scraper/adobe-stock.ts` and is gated by the `USE_LIVE_SCRAPER` env var.

- Search page: bar, sort/content/AI filters, recent searches (localStorage)

  cards, AI/Premium badges, expandable keywords with copy, contributor link

  breakdown bar
- Toolbar: select-all, sort by downloads/performance, export selected/all

- Favorites: heart toggle on cards, `/saved` page (server-backed when signed

- Heat Map: tile-sized treemap, opportunity finder, crowded niches
- Trending: keyword + niche lists with growth %
- Dashboard: stat cards + trending + quick actions

- Performance score & competition level utilities (per PRD §10.3 / §10.4)
- Prisma schema for `User`, `Account`, `Session`, `Device`, `SearchHistory`,

## Migrating SQLite → Supabase Postgres

When you're ready to deploy on Supabase:

1. In `prisma/schema.prisma`, change `provider = "sqlite"` to `provider = "postgresql"`.
2. Convert the JSON-encoded array fields back to native `String[]`:
   - `Favorite.keywordsJson: String` → `keywords: String[]`
   - `CachedAsset.categoriesJson` / `keywordsJson` → `categories: String[]`, `keywords: String[]`
   - `CachedSearch.resultIdsJson` → `resultIds: String[]`
3. Update consumers (`src/app/api/favorites/route.ts`, anywhere that uses
   `parseJsonArray`) to read the arrays directly.
4. Set `DATABASE_URL` to your Supabase connection string and run
   `npx prisma migrate deploy`.
